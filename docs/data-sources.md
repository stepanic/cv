# Where every number in this CV comes from

Numbers in `data/` go stale silently. Twice now the CV has understated real
work by a wide margin — the DOMOVINA corpus sat at "1,843 episodes / ~92,000
chunks" while the live system had grown to 3,034 / 137,451, and the profile
summary claimed 29,000 GitHub contributions against an actual 34,560.

Nothing in CI catches this, because these are *external* systems: the weekly
`stats.yml` workflow refreshes GitHub numbers only. Everything below has to be
re-checked by hand — and must be re-checked before any CV or application is
sent anywhere.

## Automated (safe to trust between runs)

| Number | File | Refresh |
|---|---|---|
| GitHub contributions, languages, top repos | `data/generated/github-stats.json` | `npm run stats:github` — also weekly in CI |
| Claude Code sessions, tokens, spend | `data/generated/claude-code-stats.json` | `npm run stats:claude` — **local only**, needs `~/.claude` + the dotclaude-backup git history |
| Public repository index | `data/generated/repos.json` | `npm run stats:repos` |

`npm run stats` runs all three.

## Manual — verify before sending anything

### DOMOVINA corpus (episodes, chunks, channels, hours, speakers)

Authoritative source is the **live MCP server**, not any local file. Call the
`server_info` tool on the Domovina_AI MCP connector, which returns channels,
episodes, chunks and the upload-date range.

For hours and speaker counts, which `server_info` does not carry:

```bash
curl -s https://stats.domovina.ai/stats.json | jq .totals
```

That snapshot is regenerated by a daily cron in `domovina-rag`, so it lags the
MCP by up to a day. Prefer MCP for episode/chunk/channel counts, the snapshot
for hours and speakers, and say "~" on the snapshot-derived figures.

Appears in: `data/profile.yaml`, `data/experience.yaml`,
`data/projects/domovina.yaml`, `domovina-rag.yaml`, `domovina-pipeline.yaml`.

**Reading, 2026-07-27:** 3,034 episodes · 46 channels · 137,451 chunks ·
~2,870 hours · 2,573 distinct speakers · corpus spans 2016-02-18 → 2026-07-10.

### Docker Hub — `microblink/api`

Built and published by Matija (Docker Hub user `stepanic`) while consulting
for Microblink; still maintained. Pull count is public and needs no auth:

```bash
curl -s https://hub.docker.com/v2/repositories/microblink/api/ | jq '{pull_count, last_updated}'
```

**Reading, 2026-07-27:** 4,157,518 pulls, registered 2017-10-30, last updated
2026-05-08.

`~/git/domovinatv/<repo>` rather than trusting the CV entry.

### FlutterFlow marketplace adoption

"1,119 FlutterFlow projects" for the BlinkID widget comes from the
FlutterFlow marketplace dashboard, which requires a login. No API — check by
hand, and treat the number as a floor.

## Enumerating Matija's own work

When rebuilding the project catalogue, these are the sweeps that found things
`data/` was missing. **Read the allow-list rule in `CLAUDE.md` first** —
consulting-client work is excluded, and the sweeps below will surface it.

```bash
# Public repos, per owner (see ALLOW_OWNERS in scripts/update-repos.mjs)
gh repo list <owner> --limit 300 --visibility public \
  --json name,description,url,primaryLanguage,stargazerCount,pushedAt,isFork

# Which orgs exist at all
gh api user/orgs --jq '.[].login'

# Cloudflare Workers per account (wrangler has no "list workers" command;
# the OAuth token in ~/Library/Preferences/.wrangler/config/default.toml works)
curl -s -H "Authorization: Bearer $TOK" \
  "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/workers/scripts"

# Cloudflare Pages projects
wrangler pages project list     # note: ignores CLOUDFLARE_ACCOUNT_ID in
                                # non-interactive mode — it returns one
                                # account's list regardless of the env var

# What was actually worked on, and when
ls ~/.claude/projects/          # one directory per project path, .jsonl per session
git -C ~/git/stepanic/dotclaude-backup log --oneline   # daily snapshots since 2026-05-12
```

Live deployments are worth verifying rather than assuming — a project entry
that links a dead URL is worse than one that links nothing:

```bash
for u in klubovi.domovina.ai zakoni.domovina.ai gis.domovina.ai; do
  echo "$(curl -s -o /dev/null -w '%{http_code}' -m 8 -L https://$u)  $u"
done
```

## Rule

Every number in `data/` traces to one of the sources above. If a claim cannot
be traced, it does not belong in the CV — see the "Keep numbers honest and
sourced" convention in `CLAUDE.md`.
